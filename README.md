## Round 011 — exact paper reserve precision
The v0.4 local-only trading form stores BUY holds as integer USDC cents and SELL holds as integer 0.000001-BTC units. Price and quantity input are parsed into BigInt scaled units (not binary floats); BUY reservations always ceil to whole cents, including micro-size orders. The screenshot/real-browser BDD checks that 64275.01 × 0.000001 BTC holds **0.07 demo USDC**, and that a fully locked demo wallet cannot accept a sub-cent extra BUY. This is only synthetic collateral arithmetic, not a real exchange settlement system. See [Round 011 report](docs/ROUND_011_REPORT.md).

## Round 012 — pre-submit local reserve transparency

## Round 018 — authenticated PostgreSQL PAPER balance **read** boundary (not released)
The new `web/api/paper-balances.js` provides an opt-in **GET/HEAD-only**, account-scoped, short-lived HMAC-signed bearer capability for a **read-only** consistent snapshot of synthetic BTC/USDC total/locked/available from the existing PostgreSQL prototype schema. It requires `PAPER_DATABASE_URL` and `PAPER_SESSION_SECRET` (server-side only), a separately migrated isolated paper DB, and trusted server-issued tokens. Missing configuration returns HTTP 503; invalid or expired capability returns 401; all writes return 405. There is **no public token issuance or persistent order API yet**. The browser remains entirely in volatile memory and continues to call only the existing read-only `/api/paper-status`. `node web/paper-balances.test.cjs` exercises negative auth/security behavior against a mocked DB; it is **not a PostgreSQL integration or public site deployment proof**.
